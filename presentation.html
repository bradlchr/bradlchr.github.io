Official Word Report Output Engine

Automated Output
  • Direct Master Template Splicing: Ingests the official 1.4 MB Deep Roots template (report_template.docx) using client-side JSZip.
  • OpenXML Reverse-Offset Splicing: Excises paragraphs and tables from highest byte offset to lowest offset, ensuring 100% XML integrity with zero document corruption.
  • Complete Directive Compliance:
    • Zero Red Text: All instructional paragraphs meant for advisors are automatically deleted.
    • Invasive Branching: Outputs Case A (congratulations message) if invasive-free; or Case B (itemized table + site notes) if invasives were found.
    • Modular Sections: Selectively includes bird baths, bee houses, or county stormwater cost-share programs based on advisor toggles.
🗣️ Speaker Notes
This is our most significant technical achievement. Other apps generate plain PDFs or markdown. Our engine takes our official Deep Roots Word template and splices client data directly into the OpenXML structure in under 3 seconds. It eliminates human error—ensuring red advisor notes never appear in a client's final document.

High-Level Technical Architecture

Engineering
  • Client-Side Serverless Zero-Build: Standalone web application delivered via GitHub Pages CDN. Zero server dependencies, no node build steps, instant page loads.
  • Cloud Firestore Database: Real-time persistence for the 185 botanical catalog, user accounts, and consultation drafts.
  • Client-Side JSZip Engine: Handles all Word OpenXML file extraction, paragraph slicing, and binary packing directly in browser memory.
  • LocalStorage Offline Resilience: Caches all plant records and consultation drafts locally so advisors never lose work when cellular coverage drops.

Security & Identity Governance

Security
  • Standalone Native Identity System: Replaced fragile third-party OAuth popups with an integrated Nature Advisor authentication system.
  • PBKDF2 Cryptographic Security: Passwords protected using PBKDF2 with SHA-256 (10,000 iterations + unique salt per user).
  • Canonical Username Schema: Enforces <first>.<last> naming with automatic collision handling (e.g. chris.bradley).
  • Two-Tier Role-Based Access Control (RBAC):
    • user (Nature Advisor): Stage consultations, edit plants, export reports.
    • admin (Program Manager): Provision new advisors, assign roles, reset credentials.
  • Hardened Cloud Firestore Security Rules: Zero-trust schema validation; users can only access their own consultation reports.
🗣️ Speaker Notes
We have implemented bank-grade password security using PBKDF2 with 10,000 hashing rounds. Our Cloud Firestore security rules ensure that public visitors have read-only access, advisors can only modify their own consultation reports, and only you as Program Manager have admin rights to provision accounts.

Leadership Q&A & Discussion

Q & A

Anticipated Leadership Questions

  • What if an advisor is on a rural property with zero cellular signal?
    Offline caching allows them to search plants, stage areas, and draft notes without internet. Edits sync back automatically once connection is restored.
  • Can clients or external visitors change our botanical data?
    No. Public visitors are locked in Read-Only Guest Mode. Only authenticated advisors can stage or edit, and only admins can provision accounts.
  • Do advisors need an iPhone or Android?
    Neither is required! The web app runs in any modern browser on smartphones, tablets, Chromebooks, Macs, and PCs.
