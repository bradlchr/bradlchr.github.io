Overall System Architecture

Client-Side Zero-Build Single-Page Application

The application follows a reactive, single-page architecture built with zero external compiler dependencies. The codebase couples real-time Cloud Firestore synchronization, persistent client-side storage, and a client-side OpenXML templating pipeline to deliver instantaneous field performance on desktop, tablet, and mobile browsers.

⚡

1. Zero-Build Frontend

Single HTML file embedding 185 baseline species, CSS tokens, reactive UI logic, and SVG iconography. Runs instantly in any modern browser without npm, node, or webpack build steps.

💾

2. Offline-First Resilience

All client consultations, advisor settings, text scale preferences, and local plant modifications are persisted in `localStorage`. Advisors can formulate entire reports without internet.

☁️

3. Cloud Firestore Mesh

Direct REST communication with Cloud Firestore using anonymous discovery for botanical browsing and authenticated endpoints for advisor roster and consultation sync.

📄

4. Client-Side OpenXML Engine

Uses `JSZip` to load the official 1.4 MB Microsoft Word template in the browser, parse internal XML structures, splice custom garden zones, and trigger native downloads without servers.

OpenXML Reverse-Offset Splicing Pipeline

`downloadDocxReport()` takes the authentic 1.4 MB Microsoft Word document template (`report_template.docx`) and converts client consultation drafts into polished `.docx` deliverables with zero backend servers.

✂️

1. Directive Red-Text Stripping

Locates and cleanly removes all instructional paragraphs styled with red font (`w:color w:val="FF0000"`), ensuring internal nature advisor advice is never shown to clients.

🔀

2. Case A vs. Case B Invasive Logic

If invasives are observed, Case A is deleted and Case B is filled with staged species and remaining Big Three vigilance advice. If invasive-free, Case B is cleanly omitted.

🔄

3. Reverse-Offset Splicing

Deletions and insertions are sorted from highest byte position to lowest (backwards). This prevents character offsets from shifting, guaranteeing 100% valid XML and zero document corruption.

📦

4. ZIP Compression & Blob Download

Updates `word/document.xml`, recompresses the archive via `JSZip.generateAsync({type:"blob"})`, and triggers client-side saving as `Deep_Roots_Consultation_[ClientName].docx`.
